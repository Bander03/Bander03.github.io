Case study

FlyRank Content Refresh Model

Ranking which pages to review first is normally a gut call. This project replaces the gut call with a transparent model, trained and validated on FlyRank's anonymized search data, then checked against a hand-written baseline so the improvement is measured, not assumed.

That jump is measured on this pipeline's own held-out split, not a claim about Google's ranking algorithm — why that matters ↓

These are the pipeline's own generated charts and numbers (see outputs/model_report.md in the repo) — decision-support for a human reviewer, not a claim about Google's actual ranking algorithm.

Behind the model — the decisions, not just the score

I chose Logistic Regression first, then Random Forest — readable baseline before a stronger model, so a wrong feature would show up early, not get buried. Baseline vs. model are compared on the exact same held-out split and metric, not separately reported numbers that happen to look good next to each other.

The hardest call: an earlier signal-audit pass found that search position does not predict click-through rate as cleanly as the industry rule of thumb assumes — CTR peaked around position 4-5, not position 1. That result directly shaped this model's feature set (position is used, but not trusted blindly).

Reported honestly, not smoothed over: Logistic Regression actually beat Random Forest at one evaluation cutoff (precision@100) despite losing at others — a real, if less tidy, result kept in the write-up rather than dropped for a cleaner story.
